# 故障复盘示例

2026-04-18，客服知识库出现多次回答不准确的问题。

排查过程发现，模型本身没有报错，Prompt 也没有明显问题。真正的问题出在检索阶段。

第一次查询只使用向量相似度检索，命中了“设备初始化说明”，没有命中“索引构建任务未完成”的故障记录。

第二次把 top_k 从 2 调整到 5 后，召回了正确文档，但正确片段排在第四位，最终回答仍然偏向前几个片段。

后来增加 rerank，并保留 source_nodes 日志后，排查效率明显提高。

这次复盘结论：

- 不能只看最终回答。
- 需要保存每次命中的 Node 和分数。
- 对故障码、产品编号、权限分组这类关键词，纯向量检索不一定稳定。
- PDF 解析质量会直接影响后续切块和检索。
